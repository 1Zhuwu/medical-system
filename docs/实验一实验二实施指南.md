## 一、改造前项目体检（4 个会让项目直接起不来的问题）

| # | 问题 | 现象 | 处理 |
|---|---|---|---|
| 1 | `pom.xml` 里 4 个 `artifactId` 用的是 **U+2011 非断行连字符**（`mybatis‑plus‑spring‑boot‑starter`、`mybatis‑plus‑generator`、`mysql‑connector‑j`、`spring‑boot‑maven‑plugin`），而不是普通的 `-` | Maven 报 `Could not find artifact ...`，依赖永远拉不下来。这是从 Word/网页复制粘贴带进来的隐形字符 | 全部改成 ASCII 连字符 |
| 2 | lombok 注解不生效 | `找不到符号: 方法 getXxx()`，满屏报错。原因有两个：Spring Boot 2.7 默认 lombok 1.18.26 不支持 JDK21+；且 **JDK 23 起 javac 默认不再隐式运行 classpath 上的注解处理器** | lombok 抬到 1.18.36，并在 `maven-compiler-plugin` 里显式声明 `annotationProcessorPaths` |
| 3 | `mysql:mysql-connector-java` 无版本号 | Spring Boot 2.7 的 BOM 管理的是旧坐标，新版已重定位到 `com.mysql:mysql-connector-j`，不写版本会解析失败/告警 | 改坐标 + 显式版本 8.0.33 |
| 4 | 源码编码 | Windows 默认 GBK 读 UTF-8 中文注释 → `非法字符` | pom 里固定 `project.build.sourceEncoding=UTF-8`；IDEA 里 `File Encodings` 也设 UTF-8 |

另外：`mybatis-plus-generator` 在 3.5.x **不再内置模板引擎**，必须额外引入 `freemarker`，否则生成器一运行就抛 `ClassNotFoundException`。

## 三、实验二：数据库设计 + 基础 CRUD

### 1. 建表 SQL

`sql/medical_db.sql`，7 张表：

| 表 | 说明 | 关键约束 |
|---|---|---|
| `department` 科室 | 编码唯一 | `uk_dept_code` |
| `doctor` 医生 | 归属科室 | `fk_doctor_dept`，手机号/身份证/工号三唯一 |
| `patient` 患者 | 患者档案 | 身份证、档案号唯一 |
| `registration` 挂号记录 | 患者+医生+日期时段 | 唯一键防重复挂号；三个外键 |
| `prescription` 电子处方 | 与挂号 1:1 | `uk_presc_reg` |
| `drug` 药品 | 库存字段留给实验三 | 编码唯一 |
| `prescription_item` 处方明细 | 一处方多药品 | `uk_item_presc_drug` |

**第三范式怎么讲（报告重点）：**
- 1NF：没有把多个药品塞进处方的逗号串，拆出 `prescription_item`；
- 2NF：全部单列代理主键 `id`，非主键字段完全依赖主键；
- 3NF：医生表只存 `dept_id`，不冗余「科室名称」；`registration.reg_fee` 是**下单时刻的价格快照**，
  属于业务事实而不是传递依赖（医生调价不应改历史挂号单金额），所以保留。

执行：

```bash
mysql -uroot -p < sql/medical_db.sql
```

### 5. 两个验收要点在代码里的落点

**① PreparedStatement 防 SQL 注入**

- 全部查询用 `LambdaQueryWrapper` / `selectPage`，MyBatis 生成 `?` 占位符，走 `PreparedStatement` 预编译，
  用户输入只被当成**参数值**，不会被当 SQL 片段执行；
- 工程里**没有一处**字符串拼接 SQL；
- 风险点：`${}` 是直接文本替换（可注入），`#{}` 才是参数绑定 —— 自定义 XML 时务必用 `#{}`。

**② 医疗敏感字段校验**

- `Doctor` / `Patient` 实体上的 Bean Validation：
  - 手机号 `^1[3-9]\d{9}$`
  - 身份证 `^\d{17}[\dXx]$`
  - 性别 `^[12]$`
- Controller 用 `@RequestBody @Valid` 触发校验，`GlobalExceptionHandler` 把 `MethodArgumentNotValidException`
  转成 `{"code":400,"message":"手机号格式不正确"}`，不会把堆栈甩给前端；
- 数据库层唯一索引兜底，`DuplicateKeyException` 也被统一捕获（防并发下"校验通过但插入冲突"）。
